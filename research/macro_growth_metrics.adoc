= Macro growth stability metrics
:revdate: 2026-09-13

== Purpose

This note records the implemented macro-growth validation layer for Issue #121.

The policy evaluation contract should not rely only on average economic growth.
Real GDP growth paths should preserve information about positive growth, downside risk,
and growth deterioration.

== Implemented diagnostics

=== Cumulative real growth contribution

Measure long-run real growth contribution separately from stability:

[stem]
++++
C_Y(p)=\sum_t \beta^{t-1}\log(1+g_t(p))
++++

=== Growth decline penalty

Penalize unnecessary decreases in the growth rate:

[stem]
++++
D_g(p)=\sum_t \beta^{t-1}(g_{t-1}(p)-g_t(p))_+^2
++++

=== Recession penalty

Track periods where growth becomes negative:

[stem]
++++
R_g(p)=\sum_t I(g_t(p)<0)|g_t(p)|
++++

== Data requirements

Canonical observed dataset:

`data/macro/real_gdp_quarterly.csv`

The current source snapshot is the Cabinet Office ESRI April-June 2026 second preliminary estimate released 2026-09-08. The table covers 1994Q1-2026Q2. The publisher leaves 1994Q1 QoQ blank because the preceding quarter is outside the table; the repository preserves that row as `source_baseline_no_qoq` rather than imputing zero. The remaining 129 quarters are `observed`.

Required fields:

* quarter
* real_gdp_growth_qoq
* annualized_growth
* status (`observed` / `source_baseline_no_qoq`; any future forecast rows must use a distinct forecast status)
* source_id
* revision_date

Observed data and forecasts must not be mixed during validation. `scripts/compute_growth_metrics.py` therefore reads only `status=observed`. Its historical validation values use beta=1; the normative discount parameter in the policy objective remains a separate pre-specified choice and is not inferred from the historical series.

== Policy event markers

Machine-readable metadata is stored in `data/policy/tax_events.csv` for:

* 1989-04-01 consumption tax introduction
* 1997-04-01 consumption tax rate increase
* 2014-04-01 consumption tax rate increase
* 2019-10-01 consumption tax standard-rate increase
* 2023-10-01 invoice system introduction

These event markers are timing metadata only. They do not identify causal effects.

== Identification caution

This dataset is for objective validation and descriptive analysis.
It must not directly claim causal effects of consumption tax changes without an identification strategy.

Possible later methods:

* Difference-in-Differences
* event study
* synthetic control

The invoice system should be evaluated separately from VAT rate changes because it changes administrative burden and compliance incentives rather than only tax rates.
