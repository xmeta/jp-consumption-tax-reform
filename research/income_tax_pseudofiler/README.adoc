= Reproducible Pseudo-filer Statutory-MTR Sensitivity Core
:revdate: 2026-09-08
:stem: latexmath

== Purpose

This directory contains a new reproducible pseudo-filer sensitivity core built
from repository-tracked official data. It is not a byte-identical restoration
of the historical V6 script.

Its scientific status is:

----
SENSITIVITY_ONLY_REPRODUCED
----

This status means that the computation is reproducible. It does *not* mean that
the latent filer population or the true filer marginal-tax-rate distribution is
identified.

== Input authority

The core uses only repository-tracked inputs:

* `data/derived/income_tax_household_type_leaf_deciles_2024.csv`
  -- 14 structural F71561 household-type leaves by 10 income deciles;
* `data/derived/estat_71561_leaf_suppressed_cells.csv`
  -- cell-level audit of all F71561 `X` markers used by the leaf compatibility
  layer, with the official disclosure-rule source attached;
* `data/derived/income_tax_bridge_deciles_2024.csv`
  -- F71911 household-size top-code sensitivity and age-65+ bridge;
* `data/derived/income_tax_decile_tax_social_instruments_2024.csv`
  -- F71531 income-tax and social-insurance moments;
* `data/derived/income_tax_2026_statutory_parameters.csv`
  -- versioned NTA 2026 statutory parameters with official source IDs,
  locators, and raw-source SHA-256 values;
* `data/derived/nta_salary_class_social_deduction_schedule_2024.csv`
  -- NTA Table 17 salary-class social-insurance averages, used only as an
  external wage-earner sensitivity;
* `data/derived/nta_salary_class_family_deduction_validation_2024.csv`
  -- 2024 NTA dependent composition revalued at 2026 statutory dependent
  deduction amounts, without forecasting 2026 eligibility changes;
* `data/derived/income_tax_age_income_source_shares_2024.csv`
  -- F71551 age-recap public-pension amount proxy, explicitly not an identified
  filer/person age allocation.

The underlying official XLSX, PDF, and HTML snapshots are stored under
`data/raw/` and registered in `data/source_catalog.csv`.  In particular,
`STAT-NSFCW-2024-USAGE-NOTES` preserves the Statistics Bureau's 2024 symbol
and confidentiality rules.

== Suppression handling

The official 2024 usage notes distinguish `-` (no applicable value), numeric
zero, and `X` (suppressed).  Aggregate household counts below 5 are displayed
as `X`; counts of at least 5 are rounded to the nearest 10.  Amounts are
suppressed when the aggregate household count is below 2.5.

The current 14-leaf compatibility layer contains 11 suppressed household-count
cells and 126 suppressed monetary cells, all enumerated in
`data/derived/estat_71561_leaf_suppressed_cells.csv`.  The pseudo-filer uses the
named sensitivity assumption
`DROP_F71561_ROWS_WITH_SUPPRESSED_HOUSEHOLD_COUNT`: the entire leaf row is
omitted when its household count is `X`.  `X` is never treated as an exact
zero.  A monetary `X` on a row with a usable count is a fail-closed error.

Using the official count-display rule, the omitted-count share is bounded
within each displayed leaf partition.  The largest strict upper bound in the
current data is below 0.16%.  This is a bound on the suppressed share of the
leaf aggregation count, not a population weight or filer share.  In deciles
where monetary values are also `X`, their effect on calibration and MTR outputs
remains `MONETARY_X_IMPACT_NOT_IDENTIFIED`; the repository does not invent a
monetary bound.  Existing numerical pseudo-filer results are unchanged under
the explicit drop sensitivity because the previous implementation had
implicitly assigned those rows zero weight.

== Construction

For each decile and scenario, the model:

. converts equivalized public aggregate income components to household-scale
  components using a scenario-specific household-size proxy;
. allocates wage, business-income, pension, and social-insurance components to
  pseudo tax units under explicit scenario assumptions;
. applies 2026 statutory income transformations and national-income-tax
  brackets;
. chooses one nuisance income scale per decile/scenario to match, or at
  statutory discontinuities approximate as closely as possible, the published/imputed
  F71561 income-tax construction moment under a named cross-concept sensitivity;
. reports pseudo-unit statutory-bracket MTR diagnostics.

The nuisance scale is a moment-matching parameter. It is not a behavioral
elasticity, causal parameter, or latent-income estimate.

== Calibration target semantics

The F71561 `income_tax_kY` target is not a directly observed household tax
liability.  The Statistics Bureau's 2024 annual non-consumption-expenditure
method states that tax/social-insurance amounts are estimated household by
household because they are not surveyed on the annual-income/assets
questionnaire.  Its income-tax construction adds Reconstruction Special Income
Tax, deducts the 2024 fixed tax reduction, and adds tax on interest/dividends
under a uniform withholding/separate-tax assumption.

The pseudo-filer tax function is a different object: 2026 ordinary national
income tax before Reconstruction Special Income Tax, and the current pseudo-tax
unit construction does not consume `interest_dividend_kY`.  The public
aggregate target does not expose the component decomposition needed to transform
it exactly to the modeled 2026 ordinary-tax concept.  The model therefore
retains the published/imputed target unchanged only under
`RETAIN_PUBLISHED_IMPUTED_TARGET_AS_NAMED_CROSS_CONCEPT_SENSITIVITY`.  No
numeric correction is invented; the concept difference is
`NOT_IDENTIFIED_FROM_PUBLISHED_AGGREGATES`.  The machine-readable audit is
`data/derived/estat_71561_income_tax_target_definition_audit_2024.csv`.

== Calibration basis

The historical V6 construction used a continuous quick-table convention.
This reproduction preserves that convention for the moment-calibration step.

The legal ordinary national income-tax calculation rounds taxable income down
to the nearest JPY 1,000 before applying the quick table. Therefore this
repository reports both:

* the continuous calibration-proxy fit; and
* the exact statutory-tax calculation at the calibrated nuisance scale.

The two are never treated as the same quantity.

The 2026 basic deduction is itself discontinuous at statutory income
thresholds. Consequently, some extreme sensitivity scenarios cannot exactly
hit the aggregate tax moment with a single nuisance scale. Such cases are
retained as nearest-achievable sensitivity diagnostics rather than smoothed
away.

== Scenarios

The reproducible core currently evaluates thirteen scenarios:

* `central`;
* `f71911_topcode10`;
* `size_lower`;
* `size_upper`;
* `business_proportional`;
* `other_wage_split2`;
* `no_social_deduction_proxy`;
* `nta_salary_social`;
* `nta_salary_dependents`;
* `pension_head_merge`;
* `pension_age_split_separate`;
* `pension_member_split`;
* `pension_member_split_f71551`.

The F71911 household-size bridge is sensitivity-only because the published
`6 persons or more` class is top-coded.  The NTA Table 17 schedules are
external wage-earner moments rather than household-decile mappings.  The
F71551 age-pension share is a proxy constructed from overlapping aggregate
age-recap cells and is not a filer-level or person-level identified share.

== Outputs

`pseudofiler_calibration.csv`:: 130 decile-scenario calibration diagnostics.

`pseudofiler_mtr_scenarios.csv`:: 130 decile-scenario statutory-MTR diagnostics.

`pseudofiler_mtr_summary.csv`:: 10-decile central values and thirteen-scenario
envelopes.

`household_worker_groups.csv`:: F71561 leaf-household worker-label aggregates.

Each output is deterministic and regenerated by
`run_pseudofiler_core.py`.

== Identification boundary

The following claims are permitted:

* the pseudo-filer sensitivity calculation is reproducible from committed
  official-source-derived data;
* under the stated calibration and allocation assumptions, statutory-bracket
  diagnostics can be generated and sensitivity envelopes computed;
* central and alternative scenario results may be used for ETI/stress-test
  sensitivity analysis.

The following claims are prohibited:

* the generated pseudo units are observed filers;
* the generated MTR distribution is the true filer MTR distribution;
* the scenario envelope is a statistically sharp identified set;
* the nuisance scale is behavioral or causal;
* the pseudo-MTR values may be used as point-identified inputs to headline
  optimal-policy conclusions.

== Historical V6 status

The historical file `18_income_tax_pseudofiler_mtr.py` remains a
`RECOVERY_GAP` because its byte-identical source and full original output
chain have not been restored.

That historical recovery gap is separate from the status of the new
reproducible core. The present implementation is independently rebuildable
from official sources and is therefore reproducible as a *sensitivity model*.

== Reproduction

[source,shell]
----
python scripts/build_source_catalog.py
python scripts/extract_estat_income_tax_tables.py
python scripts/build_income_tax_decile_instruments.py
python scripts/extract_estat_f71911_bridge.py
python scripts/build_income_tax_2026_statutory_parameters.py
python scripts/extract_nta_table17_and_f71551.py
python research/income_tax_pseudofiler/run_pseudofiler_core.py
python research/income_tax_pseudofiler/test_pseudofiler_core.py
----

A clean Git checkout must reproduce the committed outputs before the status can
remain `SENSITIVITY_ONLY_REPRODUCED`.
