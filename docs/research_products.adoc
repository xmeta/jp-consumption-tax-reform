= Research Product Boundaries
:revdate: 2026-09-12

== Authority

`data/research_products.csv` defines the stable research products in this
monorepo. `data/research_product_files.csv` defines each product's release
boundary. These files do not upgrade any scientific status; current scientific
state remains governed by `data/scientific_state.csv` and claim status by
`data/claim_graph.csv`.

== Products

`paper1` is the personal income-tax identification and robustness manuscript.
Its current `publication_status` is `WORKING_MANUSCRIPT`; promotion to
`SUBMISSION_QUALITY` is review-gated. Its claim projection is
`paper1/data/claim_registry.csv` and its reproduction entrypoint is
`python scripts/reproduce.py paper1`.

`vat_abolition` is the VAT abolition / policy-integration research product. Its
current `publication_status` is `RESEARCH_PROGRAM`; promotion to
`STANDALONE_PAPER` is review-gated. Its claim projection is
`research/vat_claim_registry.csv` and its reproduction entrypoint is
`python scripts/reproduce.py vat`.

Shared repository files may be consumed by either product. Consumption is
explicit in `data/research_product_files.csv`; a shared file used by both
products therefore has one row for each consumer. Product-private roots from one
product are forbidden from the other product's release boundary.

== Replication bundles

A deterministic product-specific archive is built with:

----
python scripts/build_product_bundle.py paper1 --output /tmp/paper1.zip
python scripts/build_product_bundle.py vat_abolition --output /tmp/vat.zip
----

Each archive contains only its declared release files plus generated
`PRODUCT_BUNDLE.json` and `PRODUCT_BUNDLE_MANIFEST.csv`. The latter records the
SHA-256 and byte size of every copied file. The default archive is an internal
replication bundle; it is not by itself a redistribution-rights decision.

For a public deposit, use `--public-release`. Raw source bytes are then excluded
unless the source audit explicitly clears inclusion, and the archive receives
`RAW_SOURCE_ACQUISITION.csv` with publisher URL, expected hash, rights status,
terms URL, attribution requirement, and reacquisition instructions. Current
policy conservatively excludes all registered external raw-source bytes. See
`docs/data_availability.adoc`. Unrelated product-private research is never copied.

Run `python scripts/validate_research_products.py` to verify product IDs, claim
projections, scientific-component links, reproduction commands, file existence,
and cross-product isolation. `python scripts/test_research_products.py` also
checks deterministic archive construction and bundle-manifest hashes.

== Archival and DOI release contract

The `--public-release` archives are deterministic deposit candidates, not evidence
that a DOI already exists. For an archival release, record the exact Git commit
and bundle SHA-256, deposit that immutable archive, then update `CITATION.cff`
with the issued DOI, release date, and release version/tag in the same release
lineage. Do not pre-populate a DOI or permissive license before it has actually
been issued or granted.

The product-specific archive contents remain defined by
`data/research_product_files.csv` and verified by the generated
`PRODUCT_BUNDLE_MANIFEST.csv` plus repository provenance/manifest gates.

== Scientific review boundary

Product release boundaries and scientific-review gates are separate controls.
A deterministic replication archive can be complete while publication promotion
remains blocked.

The review policy is defined in `data/scientific_review_gates.csv` and
`docs/scientific_reviews.adoc`. Passing `python scripts/reproduce.py paper1` or
`python scripts/reproduce.py vat` is necessary computational evidence but does
not satisfy an independent scientific-review requirement.
