= 識別ゲート付き政策評価契約
:revdate: 2026-09-14

== 正本となる評価順序

政策の「善」は税率そのものではなく、実体・分配・貧困の結果で定義する。
単一の固定重み付き loss は正本にしない。現在の正本は次の順序である。

----
identification gate
  -> viability / safety constraints
  -> multi-objective outcomes
  -> robust Pareto frontier
  -> optional secondary decision rule
----

この順序を飛ばして、未識別な outcome を一点の optimizer input にしたり、
任意の重みで「最適政策」を作ったりしてはならない。
機械可読な契約は `data/policy_evaluation_contract.csv` に置く。

== Step 0: identification gate

政策最適化へ直接入力できる outcome は、`data/scientific_state.csv` で
`maturity=READY` かつ `policy_usable=true` の component に由来するものに限る。
すなわち、直接入力集合は

[stem]
++++
A(p)=\{j:\;maturity_j=READY\;\land\;policy\_usable_j=true\}.
++++

`SENSITIVITY_ONLY` と `PARTIALLY_IDENTIFIED` は捨てないが、直接の一点入力にはしない。
それらは明示された admissible set、robustness frontier、sensitivity analysis、
break-even boundary のためだけに使う。`NOT_IDENTIFIED` は空値のまま保持する。
実装 phase が完了していても、この gate を自動的に通過したことにはならない。

現時点の active scientific-state component はすべて `policy_usable=false` である。
したがって現在の headline optimizer への direct input 数は0であり、
このIssueは未識別量を点推定へ昇格させない。

== Step 1: viability / safety constraints

人口減少それ自体を政策失敗としないため、headline の growth viability は
総実質GDPではなく、一人当たり実質GDPの成長で定義する。
人口を stem:[N_t]、実質GDPを stem:[Y_t] とすると

[stem]
++++
y_{pc,t}=Y_t/N_t,
\qquad
1+g_{pc,t}=\frac{1+g_{Y,t}}{1+g_{N,t}}.
++++

近似 stem:[g_{pc}\approx g_Y-g_N] は説明用に限り、機械検証では上の exact identity を使う。
`GDP/N` は population-normalized production/capacity であり、welfare そのものでも、
政策誘発の出生・死亡・移住効果を「除去した値」でもない。

厳密不等号は solver で直接扱わず、評価前に stem:[\epsilon_{pc}>0] を固定して

[stem]
++++
g_{pc,t}(p,\theta)\ge\epsilon_{pc}\quad\forall t
++++

を headline viability とする。policy-usable な identified set が無ければ
viability は `UNRESOLVED` であり、大きな penalty や0補完で通過扱いにしない。

総実質GDPは削除しない。市場規模、税源、debt-service capacity 等の aggregate
macro/fiscal safety は別の事前規定 guardrail として扱う。したがって
人口減少だけを理由に welfare failure と判定しない一方、aggregate capacity の
危険域も無視しない。インフレ、利払い・債務負担、JGB市場機能、為替も
constraint family / state / side effect として維持する。

政策 stem:[p] と baseline/counterfactual stem:[b] は区別する。observed/baseline
population path、policy-scenario population path、per-capita normalization を別々に保存し、
人口を固定した反実仮想を使う場合は sensitivity として identification status を付ける。

== Step 2: multi-objective outcomes

headline Pareto frontier は次の6目的だけを required とする。単一の固定重みで相殺しない。

=== Population-normalized production

年次評価期間 stem:[t=1,\ldots,T] は事前に固定し、headline では追加の時間選好を入れず
stem:[\beta_{pc}=1] とする。

[stem]
++++
C_{pc}(p)=\sum_t\log(1+g_{pc,t}(p))
++++

を最大化し、

[stem]
++++
D_{pc}(p)=\sum_t(g_{pc,t-1}(p)-g_{pc,t}(p))_+^2
++++

を最小化する。これにより、正の一人当たり成長の水準と「成長率をできるだけ
低下させない」という規範を分離する。別の stem:[\beta] を使う場合は headline を
見た後に選ばず、事前登録した sensitivity とする。

=== Household material welfare

中央値実質等価可処分所得を独立 objective とする。headline の scalar comparison は、
事前指定した評価時点 stem:[T] における baseline 比 log level effect

[stem]
++++
\Delta\log M_T^{real}(p)=\log M_T^{real}(p)-\log M_T^{real}(b)
++++

を最大化する。headline estimand は person-weighted とし、各世帯の OECD-new
annual disposable income を世帯人員の平方根で除した等価可処分所得を各世帯員へ
割り当て、その person distribution の median を使う。disposable-income definition、
equivalence scale（stem:[\sqrt{household\ size}]）、person weighting、reference year、
評価時点を固定して provenance を残す。既存NSFCW Table 7-171 の published
all-household median はこの person-weighted headline estimand の代替にせず diagnostic とする。

実質化は

[stem]
++++
M_t^{real}=M_t^{nominal}/P_t^{household}
++++

とし、VATが家計購買力へ価格経路で作用し得るため、GDP deflator を
`P_household` として機械的に流用しない。household consumption deflator / CPI family の
採用系列を結果を見る前に指定する。観測頻度を超える線形補間で policy effect を作らない。

=== Labour productivity

総労働時間を stem:[H_t] として

[stem]
++++
q_t=Y_t/H_t,
\qquad
u_t=H_t/N_t,
\qquad
y_{pc,t}=q_tu_t
++++

を保持する。headline objective は、事前指定した stem:[T] における
stem:[\Delta\log q_T(p)] を最大化する。`GDP/hour` は labour-productivity metric であり、
composition、資本深化、技術、産業構成を含み得るため「労働者自身の効率」と同一視しない。

VAT/インボイス制度について `compliance hours released -> productive reallocation -> GDP/hour`
を主張するには、`c_VAT`, `rho`, `a_alloc` 等の bridge がその scientific state を通過する必要がある。
歴史的 `GDP/hour` が再現できるだけでは VAT の causal productivity effect は識別されない。

=== Distribution and deep poverty

* `G_Y`: 所得Giniを最小化する。
* `P_2`: headline では contemporaneous median equivalized disposable income の50%を
  poverty line とする relative FGT2 を最小化する。

poverty line 自体の変化による意味の違いを隠さないため、baseline poverty line を
household purchasing-power terms で固定した `FGT2_anchored_real` を別 sensitivity/dashboard とする。
両系列を同じ estimand として混ぜない。

資産Gini `G_W` と世代間格差 `Gap_Age` は削除せず `EXTENDED_OBJECTIVE` として保存するが、
objective proliferation を避けるため現行 headline Pareto frontier の required set には入れない。
将来 headline へ昇格させる場合は contract を明示的に改訂する。

=== Aggregate growth diagnostics

Issue #121 の aggregate `C_Y`, `D_g`, `R_g` は引き続き計算・保存する。ただし
`C_pc`, `D_pc` と同名・同義にせず、aggregate capacity / recession / decomposition の
診断に限定する。`R_g` を headline Pareto objective として二重計上しない。

== Step 3: robust Pareto frontier

policy-usable な制約を満たす政策集合を stem:[F]、admissible uncertainty set を
stem:[\Theta] とする。政策 stem:[q] が stem:[p] を robustly Pareto-dominate するのは、
全ての core objective で全 admissible uncertainty にわたり no-worse で、
少なくとも一つの objective で strict improvement が成立する場合だけとする。

区間で報告する場合、最大化目的なら `lower(q) >= upper(p)`、最小化目的なら
`upper(q) <= lower(p)` を robust no-worse の十分条件として使い、少なくとも一つで
厳密不等号を要求する。必要な objective が欠ける場合は `INDETERMINATE` であり、
`ROBUSTLY_NON_DOMINATED` と読み替えない。

`research/vat_policy_integration/pareto_objectives.csv` はこの6目的だけを列挙する。
現行の8政策シナリオは必要な6目的の数値境界が揃っていないため、
`data/derived/vat_policy_pareto_screen.csv` では全て
`UNRESOLVED_NOT_ENOUGH_IDENTIFIED_OBJECTIVES` のままである。

Pareto report は少なくとも、scenario、identification gate、viability status、
利用可能な objective、欠ける objective、dominance classification、
`normative_weights_used`、`headline_optimum_claim_allowed` を分けて示す。

== Step 4: optional secondary decision rule

単一政策を選ばなければならない場合に限り、Pareto frontier の後段で
minimax regret 等を使える。

[stem]
++++
p^*=\arg\min_p\max_{\theta\in\Theta,\,w\in W}Regret(p;\theta,w).
++++

ただし、`W`、stem:[\Theta]、尺度変換、regret の utility/value mapping は
科学的事実ではなく規範・意思決定上の選択である。評価結果を見る前に明示し、
固定重み一点だけで headline optimum を作らない。現在はこの二次規則を実行しない。

== Dashboard metrics

objective と diagnostic dashboard は分離する。aggregate `C_Y`, `D_g`, `R_g`、overall real GDP、
`hours/person`、`FGT2_anchored_real`、`P_0`、`P_1`、lower-decile real income、
growth-incidence profile 等は重要だが、追加しただけで headline Pareto objective にはならない。

GDPはquarterly、所得分布はannualまたはそれ以下など頻度が異なり得る。observed、interpolated、
nowcast、model-imputed を区別し、missing years を便宜的に補間して `READY` にしない。

2023--2024の observed historical semantic regression は
`data/derived/population_welfare_historical_diagnostics.csv` に保存する。これは aggregate
real GDP が低下しても人口減少がより大きければ exact per-capita growth が正になり得ること、
`GDP/person = GDP/hour * hours/person`、GDP deflator と household CPI の分離、公開集計だけでは
FGT2を点識別できないことを再現する。全行 `optimizer_usable=false` であり causal policy effect ではない。

== 政策手段との分離

政策ベクトルは税率と制度状態を分離する。例として

[stem]
++++
p=(t_{VAT},s_{VAT}^{admin},lambda,\tau_Y,\tau_A,S_Y)
++++

とし、stem:[t_{VAT}] は税率、stem:[s_{VAT}^{admin}] はVAT固有の計算・仕入税額控除・
インボイス・申告等の行政制度状態を表す。

したがって `VAT rate = 0%` とVAT制度完全廃止は同一政策ではない。
税率0%でも行政制度を維持する場合、VAT固有事務の解放を自動仮定しない。
また JGB、所得税、資産課税、所得支援等の financing/instrument choice と
目的関数を混同しない。

制度廃止の stem:[c_{VAT}]、stem:[\rho]、stem:[a_{alloc}]、Japanのrate-cut pass-through、
objective-rank Gini/FGT2、endogenous JGB-market response 等は現在も
`SENSITIVITY_ONLY` / `PARTIALLY_IDENTIFIED` / `NOT_IDENTIFIED` の境界を維持する。
未実装チャネルを0とは置かない。

FY2024消費税収、名目GDP、incremental debt path、年間収入十分位別支出、
current-basket tax-content envelope 等の既存診断は引き続き有用だが、
その識別statusを超えて core welfare outcome に昇格させない。

== 機械検証

`scripts/validate_policy_evaluation_contract.py` は次を強制する。

* direct optimizer input は `maturity=READY` かつ `policy_usable=true` に限る。
* `SENSITIVITY_ONLY` / `PARTIALLY_IDENTIFIED` component は direct point input にしない。
* headline Pareto objectives は `C_pc`, `D_pc`, median real equivalized disposable income,
  real GDP/hour, income Gini, relative FGT2 の6つに固定する。
* wealth Gini / intergenerational gap は `EXTENDED_OBJECTIVE` として保存し、headline-required にしない。
* aggregate `C_Y`, `D_g`, `R_g` と overall real GDP は dashboard/guardrail 側に残す。
* inflation / debt service / JGB market function / exchange rate をPareto目的へ混入させない。
* dashboard、extended objectives、headline objectives を機械的に分離する。
* minimax regret は明示的な normative secondary rule としてのみ存在できる。

この契約変更自体は「最適な消費税率」を決めず、科学的stateも昇格させない。
