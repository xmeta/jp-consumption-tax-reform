= Data and Provenance Policy
:revdate: 2026-09-08

== Rule

A numerical claim cannot be promoted to a reproduced result unless its evidence
chain is stored in this repository.

The intended chain is:

----
claim_id
  -> data/claim_evidence.csv
  -> value_id / source_id
  -> data/input_provenance.csv
  -> data/source_catalog.csv
  -> data/raw/... original source file
  -> SHA-256
  -> extraction / transformation script
  -> derived artifact
----

== Directories

* `data/raw/` contains byte-preserved official source files downloaded from
  the issuing public body. Raw files are never edited in place.
* `data/derived/` contains normalized values transcribed or extracted from raw
  sources together with table/page locators.
* `data/recovery/` contains values and missing-artifact records recovered from
  the V6 handoff. Recovery data are not treated as current reproduced evidence
  unless the generating source chain is restored.
* `data/source_catalog.csv` records publisher, URL, raw file, locator,
  SHA-256, byte size, and evidence status for every raw file.
* `data/derived_catalog.csv` records every derived file, its generator,
  upstream source IDs, row count, SHA-256, and derivation status.
* `data/input_provenance.csv` gives value-level provenance for every active
  stage-1 input.
* `data/claim_evidence.csv` maps each Paper 1 claim to its evidence artifacts,
  source IDs, and value IDs.

== Evidence statuses

`RAW_OFFICIAL`:: A byte-preserved official source is present in `data/raw/`
and registered by SHA-256.

`ACTIVE_REPRODUCED`:: The result is generated by repository code from
repository-tracked inputs and is covered by tests.

`RECOVERY_ONLY`:: A value is recorded from the V6 recovery artifact, but its
generating source chain has not been restored.

`RECOVERY_GAP`:: A prior-run file is known to have existed but is not present
byte-for-byte in the repository.

Legacy byte recovery is separate from repository capability migration.
`data/recovery/legacy_artifact_capability.csv` records whether each of the 45
numbered legacy artifacts is scientifically superseded, retired, restored, or
still unresolved; an unresolved gap blocks migration only when a current active
claim still depends on it.

`NOT_READY`:: The quantity is deliberately not assigned a result suitable for
headline policy conclusions.

== Change control

When a source file changes upstream, do not silently overwrite the old raw
file. Add the new source/version, update the catalog, regenerate derived values,
and review every affected claim.

Manual transcription is allowed only when the source locator is explicit and
the row is labelled `manual_transcription_verified`. Machine extraction is
preferred for large tables such as e-Stat 7-153-1, 7-156-1, and 7-191-1.

=== F71911 top-code rule

e-Stat table 7-191-1 reports household-size categories 1, 2, 3, 4, 5, and
6 persons or more. The exact mean household size is therefore not identified
from the published size categories alone.

`data/derived/income_tax_bridge_deciles_2024.csv` uses six persons for the
6+ category only as a backward-compatible lower-side household-size proxy.
Alternative representatives 7, 8, and 10 are generated as sensitivity values.
The proxy must not be promoted to a point-identified structural input.

The age-65+ ratio in the same bridge is a published aggregate person ratio and
does not identify filer-level age composition.

=== Statutory tax parameters

`data/derived/income_tax_2026_statutory_parameters.csv` is the versioned
authority for the 2026 pseudo-filer statutory calculations. Each rule carries
an NTA source ID, locator, and raw-source SHA-256.

Machine-readable HTML values are checked against committed snapshots. Rules
transcribed from official PDFs are explicitly labelled
`VERIFIED_TRANSCRIPTION_PDF` and must retain a page/table locator. Tax-law
parameters are not allowed to remain as anonymous constants inside the research
calculation.

=== External salary-class and pension-age sensitivities

`data/derived/nta_salary_class_social_deduction_schedule_2024.csv` and
`data/derived/nta_salary_class_family_deduction_validation_2024.csv` are
derived from NTA 2024 Private Salary Survey Table 17.

They describe year-end-adjusted full-year salary earners, not F71561
equivalized-income household cells. Mapping a reconstructed pseudo-filer wage
to these salary classes is therefore an *external sensitivity assumption*, not
an identified household-decile linkage.

The family schedule reapplies 2026 statutory dependent-deduction amounts to
the dependent composition observed in 2024. It does not forecast persons who
become newly eligible under the 2026 income criteria.

`data/derived/income_tax_age_income_source_shares_2024.csv` is constructed
from F71551 age-recap cells. The 18--64 and 65+ recap household counts overlap
relative to the all-age count, so the resulting public-pension amount share is
explicitly a `SENSITIVITY_PROXY_NOT_IDENTIFIED`. It must not be described as
an observed filer-level or person-level age share.

=== NTA primary-type stage-2 and Table 3-1 point check

`data/derived/nta_primary_type_stage2_2024.csv` is transcribed from the exact
person counts in the FY2024 NTA Annual Statistics Report, Table 2-2(1).  It
reports positive-self-assessed-balance rates within the five NTA primary income-earner
categories.  These are external administrative diagnostics and do not identify
the F71561 household-to-filer selection mapping.

`data/derived/nta_positive_self_assessed_balance_income_class_primary_type_2024.csv`
reproduces the 25 total-income classes by five NTA primary income-earner
categories from the official 2024 Sample Survey Table 2 XLSX.  The 125 cells
are survey-based population estimates for persons with positive self-assessed
income tax.  They are not filer microdata and are not exact administrative
cell counts.

For every total-income class, the five category cells reconcile exactly to the
published Table 2 class total.  The five category column totals also reconcile
to the independently reproduced exact positive-self-assessed-balance totals in
`nta_primary_type_stage2_2024.csv`, and the grand total is 5,158,260.

The NTA class variable is *total income* as defined by the sample survey.  It
is not the F71561 equivalized annual household-income decile.  Any use of this
cross-tab to constrain a decile-level transport model therefore requires an
explicit bridge assumption and must remain model-contingent.

`data/derived/nta_income_class_primary_type_filing_status_2024.csv` is the
stronger administrative counterpart from FY2024 NTA Annual Statistics
Table 2-2(1).  For the same 25 total-net-income classes and five primary
income-earner categories it reports exact annual-statistics counts for:

* all persons in the Table 2-2(1) population (persons who filed or whose cases were processed by correction/determination etc. under the table's stated cutoff);
* persons with positive self-assessed income tax;
* refund filers;
* the residual that is neither positive-self-assessed-balance nor refund.

The table therefore identifies an administrative positive-self-assessed-balance rate
*within each NTA income-class × primary-type cell*.  Its 125 positive-self-assessed-balance
cells match the independently extracted Sample Survey Table 2 cells 125/125.
This is a useful cross-source consistency check, not evidence that the sample
survey cells are filer microdata.

The annual-statistics income variable is *total net income etc.* after the
definitions stated in Table 2-2(1).  It is still not the F71561 equivalized
household-income decile.  The new table materially tightens the NTA-side
stage-2 information, but it does not identify the cross-system income-rank
bridge by itself.

`data/derived/nta_table31_primary_type_rounded_2024.csv` preserves the
thousand-person values displayed in the NTA final-return press release,
Table 3-1.  Its five displayed positive-self-assessed-balance category counts sum to 5,174
thousand while the displayed grand total is 5,175 thousand.  The source notes
that totals and components can differ due to rounding.

The cross-publication composition check therefore normalizes the five
displayed categories by their own displayed sum.  The resulting maximum
difference from the exact annual-statistics composition is 0.084436...pp,
which rounds to 0.08444pp.  This is a point check only, not an independent
holdout, confidence interval, or filer-MTR validation.

== Raw-source redistribution audit

`raw_source_redistribution_audit.csv` covers every row of `source_catalog.csv`
and separates source availability from permission to redistribute committed raw
bytes. `raw_source_redistribution_rules.csv` records the domain-level terms basis.
Public-release product bundles conservatively omit raw source bytes and carry
URL + expected SHA-256 reacquisition metadata instead. See
`docs/data_availability.adoc`.

== Validation

The CI provenance gate verifies:

. every file under `data/raw/` is registered exactly once;
. every raw SHA-256 and byte size matches the catalog;
. every file under `data/derived/` is registered exactly once with its
  generator, source IDs, row count, SHA-256, and byte size;
. e-Stat 7-153-1, 7-156-1, and 7-191-1 are re-extracted from the committed raw XLSX;
. all 430 decile/component cells in 7-153-1 exactly equal the corresponding
  `00_総世帯` cells in 7-156-1;
. the 14 original leaf household types are derived from the official hierarchy,
  not hard-coded as the extraction authority;
. the F71911 household-size categories reconcile to the all-size decile person
  total within the published rounding tolerance, and the 6+/7/8/10 top-code
  sensitivity proxies are monotone;
. NTA Table 2-2(1) exact five-category stage-2 rates and Table 3-1 displayed
  thousand-person counts are regenerated and the 0.08444pp composition
  point-check target is reproduced without relabelling it as inferential
  coverage;
. NTA Sample Survey Table 2 is regenerated as 25 total-income classes by five
  primary-income categories; all 25 row partitions and all five category
  totals reconcile exactly, while the cells remain labelled survey estimates
  rather than exact filer observations;
. NTA Annual Statistics Table 2-2(1) is machine-extracted from the committed
  PDF as 25 income classes × five primary types × filing-status counts; annual
  category and grand margins reconcile exactly and all 125 positive-self-assessed-balance
  cells match the Sample Survey Table 2 extraction;
. every active stage-1 input is covered exactly once by value provenance;
. official values point to registered raw official sources;
. recovery values remain labelled `RECOVERY_ONLY`;
. every Paper 1 claim has an evidence record;
. active claims cannot rely exclusively on recovery evidence;
. all files under `data/` are tracked by Git.
